# Scenario traces and seed data

Input of the scenario player (`scripts/demo`) and the planning configuration for the center. Everything here is
generated by one command from `python-ai-service` and kept in git because other machines need it: the player reads the
traces, the center publishes `planning.json`, a demo branch is seeded from `seed.sql`.

```bash
cd python-ai-service
uv run esuo-ml generate --end-day 2026-09-20     # or: PYTHONPATH=src python3 -m esuo_ml.cli generate
```

| File | Contents | In git |
|---|---|---|
| `scenario-normal.json`, `scenario-weekend.json`, `scenario-pension.json` | Scenario traces: arrivals, duration noise, the day's shift, true world multipliers | yes |
| `planning.json` | `planning` section for `PUT /api/v1/config/global` | yes |
| `model.json` | `model` section produced by `esuo-ml fit` | yes |
| `seed.sql` | Branch reference data: services, windows, employees with the same ids as in the traces | yes |
| `history.sql` | Six weeks of service history for a branch DB, ~10 MB | no, derived |
| `holdout.csv` | Readable sample of observations | no, derived |

## Trace format

A trace is self-contained: the player needs neither `worlds/standard.json` nor a trained model.

- `arrivals` — arrival time, source, service, category and a **noise multiplier**, not a final duration: the duration
  depends on who calls the visitor, which is decided during the run.
- `shift` — a step function of which windows are open from which hour and who staffs them. Without it repeated runs
  would diverge, because the employee multiplier determines the duration.
- `duration_truth` — the world's true multipliers and the formula combining them:
  `median_sec = base × category × employee × employee_service × hour × window`, actual duration
  `median_sec × noise`. A missing key reads as `1.0`.

Durations must not be taken from `GET /admin/model`: the model is what the scenario evaluates, so the forecast would
match the outcome by construction.

## Reproducibility

The same inputs produce the same run: `--seed`, `--world` (profiles and `planned_windows` live in the world file) and
`--flow-bias` (how far the actual flow deviates from the profile, e.g. `--flow-bias pension=1.3` for "the day went
worse than planned").
