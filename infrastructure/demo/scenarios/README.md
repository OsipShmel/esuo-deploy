# Демо-сценарии стенда

Вход проигрывателя сценариев и конфигурация планирования для центра. Всё в этом каталоге порождается
одной командой из `python-ai-service` и держится в гите потому, что нужно другим людям и другим машинам:
проигрыватель читает трассы, центр публикует `planning.json`, отделение поднимается из `seed.sql`.

```bash
cd python-ai-service
uv run esuo-ml generate --end-day 2026-09-20     # или: PYTHONPATH=src python3 -m esuo_ml.cli generate
```

| Файл | Что это | В гите |
|---|---|---|
| `scenario-normal.json`, `scenario-weekend.json`, `scenario-pension.json` | Трассы демо-сценариев: приходы клиентов, шум длительности, смена дня, истинные множители мира | да |
| `planning.json` | Секция `planning` для `PUT /api/v1/config/global` (load-planning.md 3.1) | да |
| `seed.sql` | Справочники отделения: услуги, окна, сотрудники с теми же идентификаторами, что в трассах | да |
| `history.sql` | Шесть недель истории обслуживаний для БД отделения, ~10 МБ | нет, производный |
| `holdout.csv` | Читаемая выборка наблюдений для разбора глазами | нет, производный |

## Трасса

Файл самодостаточен: проигрывателю не нужен ни `worlds/standard.json`, ни обученная модель.

- `arrivals` — момент прихода, источник, услуга, категория и **множитель шума**, а не готовая
  длительность. Длительность зависит от того, кто вызовет клиента, а это решается во время прогона.
- `shift` — ступенчатая функция: с какого часа какие окна открыты и кто в них сидит. Без неё три
  прогона подряд не сходятся, потому что множитель сотрудника решает длительность.
- `duration_truth` — истинные множители мира и формула, по которой из них собирается медиана:
  `median_sec = base × category × employee × employee_service × hour × window`, фактическая
  длительность — `median_sec × noise`. Отсутствующий ключ читается как `1.0`.

Брать длительность из `GET /admin/model` нельзя: модель — это то, что демонстрация проверяет,
и прогноз сошёлся бы с фактом по построению.

## Воспроизводимость

Одинаковые вводные дают одинаковый прогон: `--seed`, `--world` (профили и `planned_windows` живут
в файле мира) и `--flow-bias` (насколько фактический поток расходится с профилем — например,
`--flow-bias pension=1.3` для сценария «день пошёл хуже плана»). Критерий готовности сценария —
три прогона подряд с одним и тем же ходом уровней (`load-planning.md` 7.2).
