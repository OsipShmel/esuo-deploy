## Ограничения проверки и следующая работа

- Docker Engine на машине недоступен: Docker CLI установлен, но Docker.app не запускается. Поэтому контейнерные образы, PostgreSQL 16, JDK 21 внутри образа и фактическое соединение NATS hub/leaf пока не проверены. Это ограничение окружения, а не подтверждённый запуск полного стенда.
- Автотесты, конкурентный нагрузочный прогон и все 10 сценариев полного MVP не выполнялись. Блокировки и ограничения реализованы, но результаты нагрузочной проверки не заявляются.
- Центр содержит только каркас и health-check. Его БД, шлюз, RPC, SSE, уведомления и синхронизация остаются задачами B следующих этапов.
- Вызов клиента, управление окнами и обработка `call_now=true` — День 2. ETA, check-in, откладывание и таймеры — День 3. Конфигурация центра/переопределения и аналитика — День 4.
- До JWT действует демонстрационный `X-Operator-Key`; QR `demo:b01` доступен только при `DEMO_DATA=true`. Публичное развёртывание этого промежуточного состояния не предусмотрено.
- `position` и `eta` пока равны null, `can_postpone=false`. Это не нулевое ожидание, а отсутствие прогноза и ещё не реализованная операция.
- Внутренний вход МП собран, но отдельно через внешнюю интеграцию не проверен: адаптер ещё не реализован.

Исправленный дизайн — `ESUO-design-doc.md`; согласованный порядок работ — `ESUO-work-plan.md`. Исходные вложения в Downloads не изменялись.


## Уточнение границы A/B

По указанию пользователя дальнейшая работа ограничена частью A: домен, application-сервисы, JDBC, миграции, конфигурация ядра, алгоритм и аналитика отделения по плану. Пакеты написанного в этой работе кода и Maven groupId — `com.dogma`. Исходная заглушка `OrderCreatedEvent` из репозитория сохраняет свой прежний пакет; она не относится к ядру очереди.

Минимальные REST-контроллеры, обработчик HTTP-ошибок и фильтр request-id были добавлены сверх части A для ручной проверки. Они остаются временным адаптером в пакете `api`, не развиваются и не считаются реализацией задач B. Их дальнейшее оформление и замена — ответственность B. Каркас центра также не развивается в рамках A.

Проект переведён с Spring Boot 4 на 3.5.16: заменены стартеры Web/Flyway и адаптирована сериализация под Jackson 2. Доменная логика и миграции не изменены. Новые тесты не добавляются.

Проверки API выше относятся к предыдущей сборке Spring Boot 4.1.1. После перехода на Spring Boot 3.5.16 выполнена чистая сборка всех модулей без тестов: BUILD SUCCESS. Приложение запущено на прежней изолированной PostgreSQL 15: readiness UP, Flyway подтвердил актуальность миграций V1/V2, каталог прочитан, прежний Idempotency-Key вернул исходный ответ 201. Сериализация сохранённых данных совместима с Jackson 2 на проверенном сценарии.
