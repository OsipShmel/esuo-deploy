# Как записать демо ЕСУО

Всё запускается одной командой на сценарий: `./scripts/demo/run.sh <код>`. Скрипт сам рассказывает в терминале, что происходит
и куда смотреть («Смотрите: …»), сам проверяет результат (✔/✘) и пишет отчёт. Ваша задача — держать на экране нужные окна
и вовремя переключаться.

---

## 0. Один раз перед записью (10 минут)

```bash
# 1. В .env должно быть:
#    DEMO_MODE=true     ← без этого демо-часы не работают: сценарии не ускоряются, pension-ab не запустится
#    DEMO_DATA=true
docker compose up -d --build              # центр + b01 + b02 + mp-simulator + notify-mock

# 2. Проверка стенда: всё должно быть зелёным
./scripts/demo/run.sh doctor
```

`doctor` ничего не меняет. Красная строка сорвёт запись, жёлтая — только один сценарий (например, без Java 25 не запустится
`analytics`). Центр должен видеть оба отделения на связи: сразу после `up` подождите около 30 секунд, пока придут первые
heartbeat.

Нужны `curl`, `jq`, `python3` (3.9+), `docker`; для `analytics` — Java 25 (`java -version`). На маке: `brew install jq`.

## 1. Раскладка экрана

Держите открытыми вкладки (логин `admin` / `operator`, пароли из `.env`):

| Экран | Адрес | Для чего |
|---|---|---|
| Сеть отделений | `localhost:8081/network` | плитки b01 и b02: уровень нагрузки, очередь, окна, аномалии, уведомления |
| Табло b01 / b02 | `localhost:8080/board`, `localhost:8090/board` | очередь глазами зала |
| Оператор b01 | `localhost:8080/operator` | окна, текущий клиент, очередь с источниками |
| Руководитель b01 / b02 | `localhost:8080/admin`, `localhost:8090/admin` | «Нагрузка», «Аналитика», рекомендация открыть окно |
| Клиент | `localhost:8080/`, `localhost:8090/`, через центр — `localhost:8081/b/b01` | запись, «мой талон», честное ожидание |
| Демо-пульт | `localhost:8080/demo` | журнал решений системы, демо-часы, сброс |

Удобно: терминал снизу на всю ширину, над ним два браузерных окна рядом.

## 2. Что и в каком порядке записывать

| # | Видео | Команда | Длина* | Главный кадр |
|---|---|---|---|---|
| 1 | Обычный день | `./scripts/demo/run.sh normal-day` | ~1 мин | табло и оператор: поток, вызовы, обслуживание на двух отделениях |
| 2 | Три источника талонов | `./scripts/demo/run.sh three-sources --pace 3` | ~30 с | запись через центр, QR и живая очередь попадают в одну очередь |
| 3 | Мобильное приложение | `./scripts/demo/run.sh mp --pace 3` | ~20 с | вебхук МП → талон → ответ в МП со ссылкой; повтор без дубля |
| 4 | Спорные ситуации | `./scripts/demo/run.sh disputes` | ~30 с | закрытие окна с клиентом, перенаправление, неявка |
| 5 | Аналитика | `./scripts/demo/run.sh analytics` | ~20 с | две недели истории → непустые отчёты руководителя |
| 6 | Обрыв связи | `./scripts/demo/run.sh link-cut` | ~1 мин | отделение живёт без центра, события докачиваются |
| 7 | Отказ уведомлений | `./scripts/demo/run.sh notify-down` | ~4 мин | breaker, DLQ, восстановление — только в реальном времени |
| 8 | Пенсионный день | `./scripts/demo/run.sh pension-day` | ~1 мин | пик, просрочки, рекомендация открыть окно |
| 9 | **Прогноз против его отсутствия** | `./scripts/demo/run.sh pension-ab` | ~4 мин | **b01 без прогноза против b02 с прогнозом** — [шпаргалка по кадрам](ab-cheatsheet.md) |

\* При паузах по умолчанию. **`pension-ab` пишите последним**: он переводит стенд в «пенсионный день» и заливает историю в b02.
Если после него нужен любой другой сценарий — сначала `./scripts/demo/run.sh normal`.

### Скорость

| Флаг | Что меняет | Пример |
|---|---|---|
| `--rate N` | скорость демо-часов: N минут отделения за минуту | `--rate 120` — день `pension-ab` за 1 мин 50 с |
| `--pace С` | пауза между шагами, секунд (по умолчанию 1,2) | `--pace 3` — успеть проговорить шаг |
| `--from ЧЧ:ММ --to ЧЧ:ММ` | отрезок дня (только `pension-ab`) | `--from 09:00 --to 11:00` |
| `--fast` | без пауз, для проверки, не для видео | |

`link-cut` и `notify-down` не ускоряются: центр живёт по реальным часам.

## 3. Что говорить в каждом видео

**1. Обычный день.** «Клиенты приходят по QR и через интернет, окна вызывают следующего. Выбор — по дедлайну ожидания,
каждый вызов объясним.» Смотрите табло и оператора; в конце — `/network`, оба отделения на связи.

**2. Три источника.** «Запись из интернета, QR в зале и живая очередь у оператора — одна очередь, одни правила.»
Экран оператора: у талонов иконки источника; экран клиента — «Мой талон».

**3. Мобильное приложение.** «МП присылает подписанный вебхук, центр передаёт запись в отделение, талон уходит обратно
в МП со ссылкой на статус. Повторная отправка не создаёт дубль, запись на прошедшее время отклоняется с причиной.»

**4. Спорные ситуации.** «Окно закрывают при клиенте — мягко (после текущего) и жёстко (клиент возвращается в очередь
на своё место). Перенаправление на другую услугу, неявка после двух повторных вызовов.» Табло и оператор.

**5. Аналитика.** «Две недели истории — и отчёты руководителя сразу непустые: сводка, загрузка окон, отклонения.»
`localhost:8080/admin` → «Аналитика».

**6. Обрыв связи.** «Связь с центром рвётся посреди дня. Зал работает дальше: табло, оператор, выдача талонов.
Клиент из интернета получает понятный отказ. Связь вернулась — накопленные события докачались.» `/network`: красная
карточка, затем снова зелёная; счётчик «в очереди на отправку» растёт и обнуляется.

**7. Отказ уведомлений.** «Провайдер уведомлений лёг: очередь работает, письма копятся в DLQ, breaker размыкается.
Провайдер вернулся — breaker закрывается, письма из DLQ досылаются.» `/network` → «Уведомления». Видео длинное:
его удобно ускорить при монтаже.

**8. Пенсионный день.** «Поток в 1,8 раза плотнее, почти половина — пенсионеры. Очередь растёт, появляются просрочки,
система рекомендует открыть окно.» Руководитель: баннер «Откройте окно».

**9. Прогноз против его отсутствия.** Главное видео про ML. Подробно — в [шпаргалке](ab-cheatsheet.md): какие экраны
в какой момент и что отвечать на вопросы.

## 4. Тесты — для видео и отчёта

```bash
cd java-backend && ./mvnw -pl node-app -am test            # автотесты отделения (нужен Docker: Testcontainers)
cd python-ai-service && uv run pytest -v                   # модель: 42 теста
./scripts/smoke/day4-center.sh                             # смоук центра на живом стенде
./scripts/demo/run.sh repeat pension-ab 3                  # три прогона подряд — одинаковая подпись
./scripts/demo/run.sh repeat normal-day 3
```

Центр автотестами не покрыт — его проверяют смоук `day4-center.sh` и сценарии `mp`, `link-cut`, `notify-down`.
Для видео с тестами хорошо смотрятся `uv run pytest -v` (длинный зелёный список) и `repeat`
(в конце — «ход событий одинаков во всех 3 прогонах»).

## 6. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| «Демо-часы выключены» / `pension-ab` не стартует | `DEMO_MODE=true` в `.env`, затем `docker compose up -d node-b01 node-b02` |
| Проверки с «статус 000», «центр видит оба отделения — ✘» | центр не поднят: `docker compose up -d center-app`, логи — `docker logs esuo-center-app` |
| `analytics`: «файл истории не создан» | в `PATH` не Java 25 — скрипт покажет ошибку генератора |
| `pension-ab`: «конфигурация не доехала за 60 с» | нет связи нода ↔ центр: `./scripts/demo/run.sh doctor`, `docker compose ps` |
| `pension-ab`: «нет history.sql» | `cd python-ai-service && uv run esuo-ml generate --end-day 2026-09-20` |
| Экраны нагрузки показывают «Пенсионные выплаты» в другом сценарии | после `pension-ab` не вернули стенд: `./scripts/demo/run.sh normal` |
| Прервали сценарий Ctrl+C | демо-часы вернутся сами, стенд перед следующим сценарием чистится автоматически; после `pension-ab` — `./scripts/demo/run.sh normal` |
| Совсем всё сломалось | `docker compose down -v && docker compose up -d --build` — чистые базы, затем `doctor` |
